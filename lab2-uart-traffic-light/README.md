# Лабораторная 2: UART. Вариант 1 «Светофор»

Задание: `SDK-1.1M_26090701.pdf`, страницы PDF 79–80 (печатные 78–79).
Подключение UART: страница PDF 15 (печатная 14).

Это продолжение первой лабораторной для **SDK-1.1M, STM32F427VIT6**.
Прикладные модули написаны на C. Файлы в `Core` предназначены для копирования
в существующий проект STM32CubeIDE `light` с заменой одноимённых файлов.
Драйвер UART собственный, регистровый, без `HAL_UART_Receive/Transmit` и DMA.

## Что реализовано

- Прежняя последовательность: красный → зелёный → мигающий зелёный → жёлтый.
- Кнопка PC15 с программным подавлением дребезга 30 мс; светодиоды PD13–PD15.
- Отключение обработки кнопки и изменение обычной длительности красного.
- UART **57600 бод, 8 бит, без чётности, 1 стоп-бит (8N1), без flow control**.
- Эхо каждого принятого байта; ответы на команды с новой строки.
- Режим опроса `P` и режим прерываний `I`, переключаемые во время работы.
- Неблокирующий приём и передача в обоих режимах. Вызов передачи помещает
  сообщение в очередь либо возвращает `false`, если места недостаточно.
- В режиме опроса выключены источники прерываний USART6 и его линия NVIC;
  SysTick продолжает работать, поскольку нужен для времени светофора.
- Кольцевые буферы RX/TX размером 512/2048 байт (полезная ёмкость 511/2047).
  Переключение I/P сохраняет их содержимое и не перезапускает USART.
- Некорректные команды, параметры, слишком длинные строки и ошибки приёма
  обрабатываются без исполнения повреждённой команды.

## Перенос в STM32CubeIDE

1. Остановите отладку кнопкой Terminate. Сохраните резервную копию проекта `light`
   вне его каталога: замена `main.c`, `traffic_light.c/.h` переключит его на лабу 2.
   Папка `lab1-traffic-light` в этом репозитории остаётся отдельной копией лабы 1.
2. Скопируйте **содержимое** `lab2-uart-traffic-light/Core/Inc` в `light/Core/Inc`,
   а содержимое `lab2-uart-traffic-light/Core/Src` — в `light/Core/Src`.
   Подтвердите замену одноимённых файлов. Не создавайте вложенный `Core/Core`.
3. **Не удаляйте** остальные файлы проекта: `stm32f4xx_it.c/.h`,
   `stm32f4xx_hal_msp.c`, `stm32f4xx_hal_conf.h`, `system_stm32f4xx.c`,
   `syscalls.c`, `sysmem.c`, `Core/Startup`, `Drivers`, linker script и `.cfg`.
   Они не включены в комплект, поскольку уже есть в проекте `light`.
4. В CubeIDE нажмите правой кнопкой по проекту → **Refresh** (F5).
   Убедитесь, что появились `console.c` и `uart_driver.c` и они не исключены
   из сборки (`Resource Configurations → Exclude from Build`).
5. Дополнительная генерация из `.ioc` **не нужна**. PC6/PC7, USART6 и NVIC
   настраиваются нашим кодом. Не добавляйте вторую инициализацию USART6 в CubeMX
   и второй `USART6_IRQHandler`: обработчик уже находится в `uart_driver.c`.
   Если переносите в другой проект, заранее проверьте, что там нет второго
   определения этого обработчика и нет периферии, использующей PC6/PC7.
6. **Project → Clean**, затем **Build Project**. Проект должен быть для
   STM32F427VIT6, с определениями `STM32F427xx`, `USE_HAL_DRIVER` и стандартным
   HAL timebase на SysTick — как ранее созданный `light`.
7. Подключите стенд к **DBG USB**. Используйте уже работающую конфигурацию
   OpenOCD и ваши `.cfg`; менять их не требуется. Запустите **Debug**.
   Если выполнение остановилось в `main()`, нажмите **Resume (F8)**.
8. Откройте COM-порт в терминале с параметрами ниже. Если открыли терминал
   после старта, отправьте `?` и Enter; стартовое сообщение могло быть пропущено.

В поставляемом `main.c` используется HSI 16 МГц, без PLL и LSE — как в текущем
проекте `light`. Частота USART берётся из `HAL_RCC_GetPCLK2Freq()`; при этой
конфигурации `BRR = 278`, фактическая скорость около 57554 бод. Настраивать
внешний кварц для этого комплекта не нужно. После переноса избегайте повторной
генерации `.ioc` с другими настройками, пока не согласуете её с кодом.

## COM-порт и терминал

USART6_TX подключён к **PC6**, USART6_RX — к **PC7**, альтернативная функция AF8.
Они уже соединены со встроенным USB-UART отладчика: отдельные провода не нужны.

1. В Диспетчере устройств найдите COM-порт интерфейса 1 отладчика SDK-1.1M.
   Он может называться `SDK 1.1M Debugger`, `USB Serial Port` или `Dual RS232`.
2. Интерфейс **0** оставьте с WinUSB для OpenOCD. Интерфейс **1** должен иметь
   драйвер FTDI виртуального COM-порта; не заменяйте его на WinUSB.
3. Откройте последовательное соединение в уже установленном терминале:
   COM вашего стенда, **57600, 8N1, flow control None**.
4. Выключите **Local echo**, иначе символы будут видны дважды: их возвращает плата.
5. Команды вводятся латинскими строчными буквами и завершаются Enter.
   Поддерживаются CR, LF и CRLF; CRLF считается одним завершением команды.
   Между словами используйте один пробел. `?` тоже завершается Enter.

## Команды

| Команда | Результат |
|---|---|
| `?` | Например: `red; mode 1; timeout 4; I` |
| `set mode 1` | Включить обработку новых нажатий кнопки; ответ `OK` |
| `set mode 2` | Игнорировать новые нажатия кнопки; ответ `OK` |
| `set timeout 8` | Обычный красный период 8 с, сокращённый 2 с; ответ `OK` |
| `set interrupts off` | Переключиться на опрос; ответ `OK`, в статусе `P` |
| `set interrupts on` | Переключиться на прерывания; ответ `OK`, в статусе `I` |
| Неизвестная команда | `ERROR: unknown command` |
| `set timeout 0`, `set timeout -1`, `set timeout abc` | Ошибка параметра, прежний тайм-аут сохранён |

Начальные настройки: **mode 1, timeout 4, I**. Они восстанавливаются при сбросе;
сохранения в Flash нет. `timeout` в ответе — обычная настроенная длительность
красного в секундах, не оставшееся время текущей фазы.

Методичка не определяет точные правила применения нового тайм-аута и уже
принятого запроса при отключении кнопки. Здесь выбраны следующие правила:

- `X` — целое число от 1 до 2147483 секунд: верхняя граница сохраняет корректное
  сравнение 32-разрядных миллисекундных сроков. Дробные значения не принимаются.
- Новый тайм-аут действует сразу. Если горит красный, его окончание пересчитывается
  **от начала текущего красного**, с сохранением признака сокращения по кнопке.
  Если новый срок уже прошёл, автомат переходит дальше без ожидания.
- Зелёный остаётся 1 с, мигание — 2 с (полупериод 250 мс), жёлтый — 1 с.
  Соотношение красного и зелёного 4:1 действует для начальных настроек;
  команда меняет именно красный период, как указано в варианте 1.
- В `mode 2` кнопка продолжает опрашиваться для подавления дребезга, но её новые
  нажатия не передаются в логику светофора. Запрос, принятый до отключения,
  не отменяется. При повторном включении зажатая кнопка не создаёт нового события:
  отпустите и нажмите её снова.

## Файлы

| Модуль | Назначение |
|---|---|
| `main.c/.h` | Запуск, HSI, кооперативный цикл и вызовы обработчиков |
| `uart_driver.c/.h` | USART6, буферы, опрос, обработчик IRQ, переключение I/P |
| `console.c/.h` | Эхо, сбор строки, проверка и выполнение команд |
| `traffic_light.c/.h` | Автомат светофора, изменяемый тайм-аут, разрешение кнопки |
| `button.c/.h` | Подавление дребезга и события кнопки из лабы 1 |
| `sdk_board.c/.h` | Кнопка и светодиоды стенда из лабы 1 |
| `custom_gpio.c/.h` | GPIO-драйвер из лабы 1, также настройка AF8 для UART |

UART ISR только перемещает байты между регистрами и очередями. Разбор команд,
формирование ответов и управление светофором выполняются в главном цикле.
`uart_write()` вызывается только из главного цикла (один производитель TX).
Секция с запрещёнными прерываниями короткая: копирование сообщения в TX-буфер
выполняется с разрешёнными прерываниями.

Очереди конечны: бесконечный поток команд без чтения ответов не поддерживается.
При нехватке TX-места консоль временно не извлекает RX-байты. При переполнении
RX или аппаратной ошибке текущая строка отбрасывается до Enter с сообщением
`ERROR`; после этого следует повторить команду. Отправляйте следующую команду
после ответа. Во время остановки на breakpoint возможны потери входных байтов;
длительности и обмен проверяйте при непрерывном выполнении (Resume).

## Ручная проверка на плате

Эти сценарии нужно выполнить после загрузки; фактические результаты пока
не получены. Отправляйте каждую команду с Enter и дождитесь ответа.

1. После сброса отправьте `?`: должны быть `mode 1`, `timeout 4`, `I` и текущий
   цвет. Наблюдайте полный цикл и реакцию кнопки, как в лабе 1.
2. `set mode 2` → `OK`, затем `?` → `mode 2`. Нажимайте кнопку во время
   красного/мигания/жёлтого: новые нажатия не должны сокращать красный.
   Проверяйте после расходования запроса, если нажимали до включения mode 2.
3. `set mode 1` → `OK`; отпустите и снова нажмите кнопку. Она снова сокращает
   ближайший красный или переводит текущий красный в зелёный после четверти периода.
4. `set timeout 8` → `OK`; `?` → `timeout 8`. Без нажатий красный 8 с;
   при запросе — 2 с. На следующем цикле без запроса красный снова 8 с.
5. `set interrupts off` → `OK`; `?` → `P`. Проверьте все команды, эхо,
   кнопку и смену цветов. Это режим опроса, прерывания USART6 выключены.
6. `set interrupts on` → `OK`; `?` → `I`. Повторите проверку. Несколько раз
   чередуйте `on/off`: ответы должны продолжать приходить без перезагрузки.
7. В обоих режимах отправьте неизвестную команду и неверные тайм-ауты:
   `0`, `-1`, `1.5`, `abc`, `2147484`, очень большое число. Должен прийти `ERROR`,
   а статус/настройки должны оставаться прежними.
8. Проверьте команду с CR, LF и CRLF: один ответ на каждую команду.
   Проверьте исправление ввода Backspace и строку длиннее 95 символов:
   ошибка не должна менять настройки, следующая правильная команда работает.
9. Проверьте несколько команд одним небольшим пакетом, например
   `set interrupts off\r\n?\r\nset interrupts on\r\n?\r\n`:
   должны прийти `OK`, статус `P`, `OK`, статус `I`, с сохранением эхо и порядка.
10. Верните `set timeout 4` и `set mode 1`; сравните поведение с лабой 1.

## Справочные источники

- Методичка SDK-1.1M: требования лабы 2 и распиновка встроенного UART.
- [ST RM0090](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf):
  глава USART; в частности, очистка RXNE/ошибок чтением SR, затем DR.

Комплект успешно скомпилирован и скомпонован под Cortex-M4 с системными файлами
и библиотеками существующего проекта `light`: 28 файлов, прикладные модули
с `-Wall -Wextra -Werror`, без предупреждений. Проверены наличие обработчиков
USART6/SysTick и логика команд и светофора отдельно от аппаратуры.
Это не заменяет проверку UART, драйвера COM-порта и временных интервалов
на реальном стенде.
